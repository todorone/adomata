# The fleet board is read-only; the buyer acts inside Meta

The Meta fleet dashboard diagnoses account health, spend, and creative performance, but never writes back to Meta — no pausing or resuming campaigns, editing budgets, or topping up balances. A buyer who spots a problem on the board goes into Meta Ads Manager to act on it. Management actions were the obvious next step once diagnosis existed, and were considered and rejected for v1: safe write paths would need a permission model, undo, and conflict handling against edits made concurrently in Meta's own UI, roughly doubling what the sync architecture and API access model have to support, and the owner interview only asked for visibility, not control. The decision is hard to unwind later — once the sync architecture and access model are built assuming read-only, adding writes means re-deriving both under Meta's actual write semantics (rate limits, propagation delay, conflicting edits) rather than extending them. It's worth recording because a dashboard that already surfaces account health and money owed reads, to anyone who wasn't in the scoping session, like an obvious candidate for one-click remediation.
