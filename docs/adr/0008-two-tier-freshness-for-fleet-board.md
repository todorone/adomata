# Two freshness tiers for the Fleet Board: 5-minute Account Tier, 1-hour Insights Tier

The Fleet Board polls Meta rather than receiving pushes (Meta's webhooks don't cover spend, insights, or campaign state — see the [rate-limit research](../research/2026-07-25-meta-api-rate-limits-fleet-refresh.md)), so every figure on the board is only as fresh as its last poll. Rather than one refresh interval for the whole board, Account Health, money owed, and campaign running-state (Account Tier) poll every 5 minutes; Spend and KPIs (Insights Tier) poll hourly. This was resolved with the agency owner ([issue #8](https://github.com/todorone/adomata/issues/8)): a blocked account or stopped campaign is a break the media buyer needs to catch fast, while spend/KPI numbers tolerate an hour precisely because none of the three personas watch the board continuously — they check in opportunistically a few times a day. Splitting the tiers also matches the Meta API's own cost structure: Account Tier fields are cheap baseline Ad Account reads, while Insights Tier fields are Insights calls competing against the undocumented backend throttle that is the fleet's real rate-limit ceiling. A single uniform interval would either poll Account Tier data too slowly to catch a break, or poll Insights Tier data needlessly often against the more constrained budget. The split is hard to unwind later — the sync architecture (two loops, two schedules, per-tier last-refreshed timestamps) is built assuming it — and non-obvious to a future reader who might otherwise assume one refresh loop for the whole board.
