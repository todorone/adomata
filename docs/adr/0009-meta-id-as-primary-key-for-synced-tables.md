# Vendor-synced tables use Meta's own id as the primary key

Ad Account, Campaign, Ad Set, and Ad are synced from Meta, and each already carries a globally-unique id from Meta itself. Rather than minting an app-generated surrogate id and a separate unique external-reference column, these tables use Meta's own id string directly as the primary key (e.g. `ad_account.id = 'act_123456789'`). This matches the vendor-mirror philosophy already established for these entities (CONTEXT.md: Adomata stores Meta's own names as-is) and makes every sync a plain upsert keyed on Meta's id, with no id-mapping table to keep consistent. It was considered and rejected to instead follow Adomata's own uniform id shape (used for app-originated entities like Client) here too, since nothing about these rows is ever created by Adomata — a surrogate id would only add a join, not a behavioral benefit. The trade-off: these tables' primary keys are opaque vendor strings rather than Adomata's usual id shape, which a future reader might not expect at a glance.
