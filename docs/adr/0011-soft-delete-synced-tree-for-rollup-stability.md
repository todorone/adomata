# Campaign/Ad Set/Ad are soft-deleted, never hard-deleted, to keep historical rollups stable

Meta lets advertisers delete or archive Campaigns, Ad Sets, and Ads, and Insights rows are keyed at Ad grain by Meta's own Ad id ([ADR 0009](0009-meta-id-as-primary-key-for-synced-tables.md), [ADR 0010](0010-insights-stored-at-ad-grain-only.md)). Campaign/Ad Set/Ad rows are soft-deleted — a `deletedAt` marker set the first time a sync no longer sees the object — rather than removed, so a deleted Ad's historical Insights rows stay joinable and past Client/Ad Account rollup totals for prior days never shrink retroactively just because an advertiser cleaned up their Ads Manager after the fact. Hard-deleting on disappearance was the obvious default and was rejected specifically because it would silently corrupt already-reported historical numbers, which reads as a correctness bug rather than a storage choice to anyone debugging a KPI total that changed with no corresponding spend. The board's live tree view filters out soft-deleted rows; only rollup queries over past dates still join through them.
