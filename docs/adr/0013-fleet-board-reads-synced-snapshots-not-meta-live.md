# The Fleet Board reads synced snapshots, not Meta live

Every figure on the Fleet Board is read from Adomata's own database, populated by the Account Tier / Insights Tier sync loops ([ADR 0008](0008-two-tier-freshness-for-fleet-board.md)), never fetched from Meta synchronously on page load. This was the live-passthrough-vs-snapshots fork raised in [issue #12](https://github.com/todorone/adomata/issues/12): a board over 30–150 Ad Accounts fanning out into a live Meta call per account on every page load would put one slow account's latency under every render, share a single rate-limit budget across however many users load the board at once, and give no graceful behavior when Meta itself is slow — none of which a snapshot has to deal with, since it just reads its own last poll. The [rate-limit research](../research/2026-07-25-meta-api-rate-limits-fleet-refresh.md) confirms the sync side is affordable (roughly 300–750 calls for a full 150-account refresh, comfortably inside a 5–15 minute floor), so there was no cost pressure pushing back toward live reads. ADR 0008 already assumed this architecture implicitly (per-tier last-refreshed timestamps, two independent poll loops); this ADR makes it the explicit, named answer to the fork rather than leaving it inferred.
