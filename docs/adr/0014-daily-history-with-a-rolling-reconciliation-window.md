# Insights history is stored as daily rollups with a rolling Reconciliation Window, not write-once

The Insights Tier stores one row per Ad per day ([ADR 0010](0010-insights-stored-at-ad-grain-only.md)), not just a latest-value snapshot — but a day's row isn't written once and left alone. The [Reconciliation Window](../../CONTEXT.md#freshness) is the current day plus the 28 complete prior days; it keeps being re-polled and overwritten on every Insights Tier cycle, and every day inside it is Provisional. An aggregate is Provisional whenever any included day is Provisional. Meta's own docs state that Insights may change for 28 days after being reported, and a settled day's number can also move after an advertiser edits an ad set's attribution setting or Meta makes a platform-wide attribution change (see [insights-metrics-by-level.md §4](../research/insights-metrics-by-level.md#4-attribution-windows)), so a shorter window risks silently drifting from what Meta would report if asked again. Fetching history on demand instead of storing it was considered and rejected: it reopens the exact problems [ADR 0013](0013-fleet-board-reads-synced-snapshots-not-meta-live.md) ruled out for the live path (latency under a click, unpredictable load on the same throttled Insights endpoint from multiple users requesting overlapping ranges). A day older than the window is stored as-is and never re-checked again — the residual risk of a rare, out-of-band revision reaching that far back is accepted for this scope, not engineered around.
