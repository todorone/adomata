# Meta API is faked via network-level interception, not a swappable client interface or a separate fake server

In dev and E2E, the running API process must never call real Meta endpoints, but the sync loop's rate-limit-header parsing and adaptive backoff (see [rate-limit research](../research/2026-07-25-meta-api-rate-limits-fleet-refresh.md)) need to actually run against something, not be skipped. We intercept outbound HTTP calls to Meta at the network layer (e.g. MSW in Node mode) inside the same API process, rather than swapping in an in-memory fake client behind an interface (which would bypass the header-parsing/backoff code entirely, since a fake would just return a domain object, never a header) or running a second standalone fake-server process (extra infrastructure to start/stop/manage for no coverage gain over interception). The real `MetaClient` — real `fetch`, real retry/backoff, real header parsing — runs unchanged in every environment; only the wire response is substituted. This also keeps the fork to a single point at process startup rather than scattering environment checks through the sync logic, matching [ADR 0013](0013-sync-driven-by-heartbeat-not-workers-native-cron.md)'s "no dev-only code path" bias.
