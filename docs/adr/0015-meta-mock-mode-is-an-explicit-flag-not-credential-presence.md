# Meta mock mode is an explicit flag, not inferred from credential presence

Whether the API process talks to real Meta or the network-level fake ([ADR 0014](0014-meta-api-faked-via-network-interception.md)) is decided by a dedicated startup-time flag (`META_API_MODE=fake|live`), not by whether `META_APP_ID`/`META_APP_SECRET` happen to be set. [auth.ts](../../apps/api/src/logic/auth.ts) already infers Google/Apple login from credential presence, and that pattern was considered here — but the failure mode differs: a social-login provider left unconfigured just disables a feature, while an environment meant to be real (a Coolify preview/staging deploy) that's missing a Meta credential would silently start serving fabricated data as if it were genuine, with nothing to notice. The explicit flag makes that mistake loud instead: a `live`-mode process with no credentials fails to start rather than quietly faking. Local dev and E2E set the flag to `fake` in their own `.env`; production sets it to `live`, with no default that lets either side of that choice happen by accident.
